### Introduction
I recently passed the HTB COAE (Certified Offensive AI Expert) certification. It was one of the harder certifications I've done, and I learned a lot about AI, LLMs, and machine learning by doing it. I'll tell you about my experience with the course content and the exam, and then share some thoughts that might be useful for anyone considering going through this training.

Now, when I speak about difficulty and effort, I have to provide some information about my skillset and educational context upon starting the certification path, so that you can understand what I mean by those terms. I work full time as a penetration tester, I have some red team/pentesting certs, I have used LLMs but never dived too much into the underlying technology, and in college, I barely passed Calculus II with a C-, after which I spent the next 10 years happily not doing any math beyond basic algebra and trigonometry. This last point is important because there are a lot of equations and mathematical concepts in the course material: I knew nothing about PyTorch, tensor calculus, or Jacobian matrices going into this. Now, of course, I'm much more comfortable working with PyTorch, training models, and testing them. 

### Course Content
I did the course in two halves with a long gap in between. The first few modules that covered the foundations of AI, prompt injections, and output attacks came out last year, and, being new to this aspect of penetration testing and the inner workings of AI/LLMs, I did them right away. Then I moved onto other things, and only came back in July after I found out that the path had been expanded with new modules and a certification at the end. These first six modules are all well written, and cover the basic attack patterns for testing various AI systems. There is nothing overly complicated here, and it provides a solid overview of jailbreaks, prompt injections, and abusing various AI integrations. However, there are some notable omissions in the course content for these LLM-focused modules: there is no material on attacking RAG pipelines or multi-agent/orchestrated systems. 

The second half of the course focuses on adversarial attacks on machine learning systems, followed by fine-tuning methods to resist adversarial attacks and avoid leaking training data. If you've read articles on hackernews about things like the shirts that confuse facial recognition models and stickers that block automated license plate readers, this is where you'll learn how this stuff actually works. I found this all really interesting, which gave me the motivation to push through the course material and learn about how it all works. That said, the main problem with the AI evasion and privacy modules is that they are not very well written from a didactic perspective. I think this is why a lot of people struggle with these later modules, and as I was struggling with them too, I began to suspect that parts of them were written with AI. I got this feeling after a long stretch of page after page of the modules following a consistent pattern. An algorithm would be introduced, then a python code block, then a short explanation of the code block, and then another code block. Then some more code blocks, and more verbose explanation of how the code blocks generate a visualization for the code blocks you read earlier. It felt like what you would get if you pasted in a code block into an LLM with a prompt like "explain what this code does", rather than what you would see in a technical manual or book where you might be given some annotated code, and the text explains the "why" and "how" along with what the bigger picture is.  

A particularly egregious example was a section with a python chunk that was essentially
```python
for i in range(1, num_items):
	if I[k] == value:
		continue
```
followed by an entire paragraph explaining that the loop starts at one and goes through the number of items, if `I[k]` equals a value the rest of the code in the for loop must be skipped, and then another sentence explaining what the `continue` keyword does in python. I eventually just ended up copying the code into my own Jupyter notebook, skimming the explanations, and then read some books to fill in the gaps. I wouldn't say doing outside reading is necessary, but for me, it made the difference between actually feeling like I was understanding the concepts, versus getting just enough handle on things to muddle through and pass the module assessments.

The books that I highly recommend:
- "Math for Deep Learning" by Ronald Kneusel. Like I said, I've never been that good at math, and I read the sections on tensors, backpropagation, and gradient descent to get a better handle on it. After doing that, the equations in the course weren't as mystifying. 
- "Deep Learning Crash Course" by Volpe et al. This explains how to use PyTorch to build and use various types of AI/ML systems. You get some of this information in the introductory modules, but it's explained much better here. After reading this, I was no longer constantly messing up my dataloaders, batches, labels, etc. and getting stuck on PyTorch errors.
- "Build a Large Language Model (From Scratch)" by Sebastian Raschka. This explains LLMs and transformers in depth, and is overall an incredible resource.

These aren't required for completing the modules, it just was the most effective way for me to learn, and may be helpful for anyone that wants some more in-depth explanations. These are complicated topics and the nature of HTB modules necessarily leaves out the type of comprehensive explanations that a book-length treatment of these subjects can give you. 

### Exam
This was the first HTB exam I've done. I initially wasn't sure that I wanted to bother with it at all, but after struggling for three months to learn all this stuff, I wanted a little bit of validation and something unique to have, and it's cheaper than OffSec's OSAI. 

I passed the exam on my second attempt. The first attempt didn't go well for me, for a few reasons. My original plan was to start saturday afternoon, get most of the exam done over the weekend, and then during the workweek do whatever was left and finish the report. The problem was that I was out of practice for this type of exam. I used to love doing HTB boxes, the seasonal challenges, and CTF challenges. But this year I had a lot of other stuff going on (personal research, talking at BSides312, moving cities, changing jobs, etc) that took up my focus and didn't leave me with a lot of time or motivation to pwn boxes. At any rate, the end result was that when I started the exam and hit the first challenge, I felt really out of practice. I used to have no problem solving medium/hard HTB boxes, but when I looked at the way the web app on the exam was built, and what I was supposed to do, the mental connections and intuition that I used to have weren't coming to me like they did when I was solving one or two boxes a week. So I made very little progress over the weekend, and then the workweek turned out to be much busier than anticipated, so I left it at that and figured I'd do some more review and give it another go.

In preparation for the second attempt, I did a few easy HTB boxes, just to get back into the flow of the HTB style, `cat user.txt`, and so on. You have to execute basic web application attacks on the exam, but it's nothing complicated, and I didn't prepare with anything specific: I just picked a few random easy-level boxes focused on web exploitation that I hadn't solved before. Then, I did a review of the AI Evasion modules. The first go around, I made it through the assessments, but as I mentioned above, I hadn't really mastered it. My biggest problem wasn't the attacks themselves, but the data processing pipeline and working with PyTorch objects. There's a lot of converting tensors to arrays, converting arrays to images, converting images to tensors, and applying normalizations or changing dimensions in between steps. So I repeated all the AI evasion modules, making sure I actually understood what was going on in each step, and in what type of situation each attack would be most useful.

The actual second attempt went a lot smoother. I decided to start on a Thursday evening after work, and got the first flag in an hour. I worked a little more on Friday and got two more flags, and on Saturday I made the final push and ended up with 6/7 flags. I wrote the first draft of my report on Sunday, did the final edits and review over Monday and submitted on Tuesday. I used the Sysreptor COAE template, which kept me on track for making sure I had everything in the report I needed.

About three weeks later, I got my passing grade and certificate:

### Exam/Course Tips
A few tips I can offer for anyone planning on doing this:
1. Create wrappers and python modules for each of the adversarial ML attacks. If you followed along with the modules, you're going to end up with sprawling jupyter notebooks full of visualization plots, dataloaders, training loops, sample checks, and random tests. When it comes time to execute one of these attacks in a novel situation, you're going to have a really hard time trying to sort through what you did. I moved all of the attack logic to a new python file, and then imported that as a python module into a jupyter notebook with separate cells for the data processing pipeline, training, attack, and output. This allows you to easily make changes to adapt your attacks, and gives you a clearer mental picture of what's going on. 
2. Do one or two easy HTB boxes to warm up. The exam requires you to pull off some basic web attack techniques, and you'll need to get back into the flow of getting flags. 
3. Pay attention to normalization and data processing. When you do the challenges it's very easy to get mixed up whether you're working in `[0,1]` pixel space or normalized space. It's also easy to get things mixed up when working with RGB images and wonder why your array dimensions are all screwed up and nothing works.

### Conclusion
I learned a lot by doing this certification. After I finished, I was much more comfortable working with LLMs and other ML systems, and I felt I had a solid foundation for how to attack them. I also now feel confident in my ability to read arxiv papers on the latest attack methods. That said, a lot of the material on AI evasion and privacy is outside the scope of practice for red team/penetration testing engagements, and more suited for people working in the AI/ML engineering or development space. If you're looking for a strictly red team oriented course, then one of the other certifications might be a better fit. I can't make any certain judgments yet, since this area of pentesting is still so new, and it remains to be seen what types of red team engagments companies will need for their AI deployments.
